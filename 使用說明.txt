記帳／開票工具 v1.0.8

啟動及首次升級
1. 從 v1.0.7 或更早版本升級到 v1.0.8，必須使用完整資料夾更新，不能只換 HTML。
   舊版 Python 只懂 HTML 更新，無法自行安裝新版 Python。
2. 關閉原本啟動工具的終端機視窗，再執行「啟動記帳工具.command」。
3. 繼續使用相同瀏覽器及本機網址 http://127.0.0.1:8765，原有帳本仍保存在瀏覽器。

設定
頂部記帳／開票左邊新增 Setting，可選擇首頁「列表」或「格子」。
設定立即生效，保存在此瀏覽器，不影響帳本資料。

檢查與安裝更新
「檢查更新」讀取 GitHub 的 version.json，逐檔比對獨立版本號及 SHA-256。
只下載需要更新、缺失或損壞的程式檔案；未變更檔案不會重複下載。
全部所需檔案下載並驗證後，檢查按鈕旁才會出現「手動更新」。
點擊後顯示「更新中…」，安裝完成才消失；失敗則保留按鈕並顯示錯誤。
開著頁面時不會自動安裝；關閉所有記帳頁面後會自動安裝已準備好的更新。
Python 更新後服務會自行重新啟動。HTML 頁面仍會等輸入及導入完成、閒置後安全刷新。
更新前的程式會保存至「系統檔案/.update-backups」。驗證失敗不會安裝；安裝失敗會還原。

發布更新（GitHub ledger-updates 儲存庫）
將提供的 GitHub 發布包解壓，把裡面的所有檔案依原路徑上傳。
先上傳程式檔，最後上傳 version.json，避免清單先發布但檔案尚未就緒。
version.json 的 files 列出全部隨程式發布的檔案，每筆都有：
  path：安裝到工具資料夾的相對路徑
  version：該檔案的獨立版本號，格式 x.y.z
  url：該檔案的 GitHub HTTPS 下載網址
  sha256：檔案實際內容的 SHA-256
  executable：是否為可執行檔
只修改部分檔案時，只提高那些檔案的 version 並更新其 sha256；其他檔案保留原版本和摘要。
頂層 version 是整體發布版本，可增加到下一版。發布時仍應列出未變更的程式檔案。
同一檔案的內容變動必須提高它自己的版本號；不會將檔案降級。
version.json、瀏覽器帳本、雲端備份、暫存檔、.update_state.json 不屬於被覆寫的程式檔。
